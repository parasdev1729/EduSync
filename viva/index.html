Hashing vs Encryption

Hashing (One-Way): Irreversible fixed-length output fingerprint. You cannot decrypt it. Used to secure database passwords (e.g. bcrypt).

Encryption (Two-Way): Reversible cipher transformation. Plaintext can be restored using decryption keys. Used for secure network transport (e.g. SSL/HTTPS).

Authentication vs Authorization

Authentication (Identity): "Are you who you claim to be?" Verified via login IDs, password hash matching, and OTP validation.

Authorization (Privilege): "Are you allowed to run this action?" Verified via checking user roles (Student vs Teacher vs Admin) on routes.

WebSocket vs Socket.IO

WebSockets (Protocol): Standard TCP networking protocol (ws://) for full-duplex bi-directional streams. Lacks groupings or fallback handlers.

Socket.IO (Library): Wrapper adding automatic reconnects, rooms partitioning, event namespaces, and HTTP long-polling fallback safeguards.

Quick Pitch Summary

"EduSync is a full-stack academic portal built on the MERN stack (React, Node, Express, MongoDB). For session management, we use **JWTs** (stateless tokens) divided into short-lived access tokens kept in React memory and long-lived refresh tokens in **HttpOnly cookies** (blocking JavaScript access/XSS). API communications are driven by **Axios** (which uses response interceptors to refresh access tokens on 401 errors automatically). We run **Socket.IO** for real-time notifications, placing clients in role-specific **Rooms** (like 'admins' or 'batch:CSE') to push notifications instantly without client-side polling."

HTTP & Web Engineering Glossary

Quick search table for HTTP status codes, standard methods, and stack terminology.

Important HTTP Methods (Verbs)

GET Requests representation of the specified resource. Requests using GET should only retrieve data and have no other effect. (e.g. fetching attendance logs).
POST Submits data to be processed to the specified resource, frequently resulting in creation of records or side-effects (e.g. logging in, sending OTPs).
PUT Replaces all current representations of the target resource with the uploaded request payload. Used for full updates (e.g. editing teacher profile details).
PATCH Applies partial modifications to a resource. Unlike PUT, only specified fields are altered (e.g. updating a request status flag from pending to approved).
DELETE Removes the specified resource from the backend server database (e.g. deleting a user account).

Important HTTP Status Codes

200 OK Standard request succeeded. Represents data successfully fetched and sent.
201 Created Request succeeded and a new database resource was created (e.g. new circular added).
400 Bad Request Server cannot process request due to client side validation fail (e.g. missing inputs or weak password).
401 Unauthorized Identity validation failure. Token is missing, expired, or invalid. Calls for login redirect or refresh.
403 Forbidden Identity is verified but the user lacks access rights/role privileges (e.g. student calling user delete route).
404 Not Found The requested server endpoint resource does not exist in backend paths.
500 Server Error Backend server crashed or encountered database exceptions trying to fulfill the API logic.
